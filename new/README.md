# מערכת הערכת סיכון בשיחת שירות בנקאי (Flask Prototype) - VeriCall

פרויקט גמר בתחום סייבר ומערכות מידע. מטרת המערכת לסייע לנציג מוקד שירות בנקאי
להעריך בזמן אמת את רמת הסיכון בשיחה עם לקוח (חשד להתחזות), ולקבל המלצה האם
להמשיך בתהליך הרגיל, לדרוש אימות מוגבר או להסלים את האירוע.

המערכת כוללת שני מסלולי עבודה:
1. **תיעוד ידני** (`/call/new`) - הנציג מסמן בעצמו אינדיקציות בסיום שיחה, לצורך תיעוד.
2. **סימולטור מוקד חי** (`/dashboard`) - מדמה שיחות נכנסות עם אינדיקציות אוטומטיות
   (שעה חריגה, שיחה מחו"ל, שינוי מיקום, החלפת מכשיר/SIM, ריבוי שיחות קצרות, קול סינתטי)
   שמופיעות בזמן אמת תוך כדי השיחה - ומציגות לנציג את רמת הסיכון עוד לפני שהוא עונה,
   בדיוק כפי שתואר בסקירת הספרות (ניצול זמן ה-IVR/ההמתנה לצורך הערכת סיכון מוקדמת).

בנוסף:
- **אימות מוגבר אוטומטי (Step-Up)** - כאשר רמת הסיכון מחושבת כ"בינונית", המערכת שולחת
  אוטומטית בקשת Push לאפליקציית הבנק הרשומה. הקוד אינו מוצג לנציג ואינו נשלח לדפדפן.
- **מסך ניתוח דפוסים** (`/analytics`) - מנתח את כלל השיחות שתועדו ומאתר דפוסים
  שעשויים להעיד על ניסיון תקיפה: התפלגות רמות סיכון, האינדיקציות השכיחות ביותר,
  לקוחות עם פניות חוזרות, ושיחות בסיכון גבוה אחרונות.

## טכנולוגיות
Python 3.8.10 ומעלה, Flask 3.0.3, Jinja2, HTML, CSS, JavaScript פשוט (fetch + polling, ללא WebSocket), SQLite.

## התחברות למערכת
המערכת דורשת התחברות (`/login`) לגישה למסכי העבודה הפנימיים. משתמש קבוע להדגמה:

```
שם משתמש: agent
סיסמה: 1234
```

## התקנה והרצה

יצירת סביבה וירטואלית:

```
python3 -m venv .venv
```

הפעלה (Mac/Linux):

```
source .venv/bin/activate
```

הפעלה (Windows PowerShell):

```
.venv\Scripts\Activate.ps1
```

התקנת תלויות:

```
pip install -r requirements.txt
```

הרצת האפליקציה (רצה בפורט 5050):

```
python app.py
```

או:

```
flask --app app run --host 0.0.0.0 --port 5050
```

לאחר ההרצה גשו לכתובת:

```
http://127.0.0.1:5050
```

## נתיבים עיקריים

| נתיב | שיטה | תיאור |
|---|---|---|
| `/` | GET | דף הבית (ציבורי) |
| `/user/<name>` | GET | דף ברוכים הבאים דינמי לפי שם (ציבורי) |
| `/login` | GET/POST | התחברות למערכת |
| `/logout` | GET | התנתקות |
| `/compare` | GET | השוואת אימות ידע, 2FA קבוע ו-VeriCall |
| `/dashboard` | GET | לוח בקרה חי - בחירת תרחישי שיחה להדגמה |
| `/dashboard/start/<scenario_id>` | POST | התחלת סימולציית שיחה חדשה |
| `/dashboard/call/<call_key>` | GET | מסך מעקב חי אחר שיחה בודדת (מד סיכון מתעדכן) |
| `/dashboard/call/<call_key>/finish` | POST | סיום השיחה החיה ותיעודה בבסיס הנתונים |
| `/api/dashboard/live` | GET | JSON - כל השיחות הפעילות כרגע (ללוח הבקרה) |
| `/api/live-call/<call_key>` | GET | JSON - מצב שיחה חיה בודדת (מאותחל ע"י JS כל שנייה) |
| `/api/live-call/<call_key>/step-up/<result>` | POST | אישור/דחיית Push מדומה (`approved`/`failed`) |
| `/analytics` | GET | ניתוח דפוסים על כלל השיחות - זיהוי סימנים לניסיון תקיפה |
| `/audit` | GET | יומן ביקורת של החלטות המערכת ופעולות הנציג |
| `/call/new` | GET/POST | טופס תיעוד ידני של שיחה + שמירה וחישוב סיכון |
| `/call/<id>` | GET | תוצאת הערכת הסיכון לשיחה (ידנית או חיה) |
| `/calls` | GET | רשימת כל השיחות שנשמרו |
| `/api/score` | POST | חישוב סיכון חי לטופס הידני (משמש fetch מה-JS) |

כל הנתיבים הפנימיים (מלבד `/`, `/user/<name>`, `/login`) דורשים התחברות.

## בסיס הנתונים והעברה ל-Linux

בסיס הנתונים `bank_risk.db` נוצר אוטומטית בהרצה הראשונה. עבור חבילת ההדגמה למרצה
יש להעביר גם את הקובץ הזה, משום שהוא מכיל את היסטוריית השיחות, הערכות הסיכון ויומן הביקורת
שדרושים למסך ניתוח הדפוסים. הקובץ נמצא ב-`.gitignore` כדי למנוע העלאה אוטומטית של נתונים,
אך ניתן להעביר אותו ידנית כחלק מחבילת ההדגמה.
מבנה הטבלאות והקשרים מפורטים ב-[erd.md](erd.md).

להעברת הפרויקט לשרת Linux:

```bash
cd חדש
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pytest -q
python app.py
```

אין להעתיק את `.venv/`, `__pycache__/` או `.pytest_cache/` מהמחשב המקומי.
את `bank_risk.db` יש להעתיק בחבילת ההדגמה אם רוצים לשמר את היסטוריית הנתונים.
`python app.py` מאזין על `0.0.0.0:5050`, כך שניתן לגשת אליו גם ממחשב אחר ברשת באמצעות
כתובת ה-IP של השרת, אם חומת האש והרשת מאפשרות זאת. זהו שרת הפיתוח של Flask לצורכי הדגמה
בלבד; אין להשתמש בו בסביבת production. יש להגדיר `SECRET_KEY` דרך משתנה סביבה בשרת.
